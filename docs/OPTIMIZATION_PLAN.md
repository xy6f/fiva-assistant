# FIVA Assistant 优化计划（简化版）

> 只改代码和加新表，不动配置文件。

## 要做的事（按顺序）

| 顺序 | 做什么 | 解决什么问题 | 怎么做（一句话） |
|---|---|---|---|
| 1 | AI 能查真实账目 | AI 回答全靠编，看不到你的真实数据 | 给 AI 加"查询工具"，它需要数据时自己去数据库查 |
| 2 | 角色权限 | 现在四种角色没区别，谁都能改数据 | 后端接口加权限检查，前端菜单按角色显示，VIEWER 只能看 |
| 3 | 报表算数修正 | 报表数字可能算错、很慢 | 用数据库汇总代替全量计算，加"资产=负债+权益"自动校验 |
| 4 | 科目模板入库 | 科目列表写死在代码里 | 建一张模板表，启动时从表里初始化科目 |
| 5 | 税率规则入库 | 税率写死在代码里，改政策要改代码 | 建税率表 + 映射表，程序从表里读税率 |
| 6 | OCR 识别改进 | 解析 AI 返回结果的方式太脆弱 | 换成标准 JSON 解析 + 记录可信度 + 样本测试 |
| 7 | AI 统计用真数据 | 页面上的 Token 数、成功率是假的 | 每次调 AI 记一笔日志，页面显示真实统计 |
| 8 | 操作审计 | 出了问题不知道谁改的 | 自动记录：谁在什么时候改了什么 |
| 9 | 错误提示友好化 | 报错直接显示 500，很难看 | 统一错误格式返回中文提示；列表加分页 |
| 10 | 凭证编号防冲突 | 并发时凭证编号会重复 | 建序列表领号，保证编号唯一 |
| 11 | 测试和 CI | 改代码怕改坏没有保障 | 补单元测试 + GitHub 自动跑测试 |

## 新建的表（5 张）

1. `t_subject_template` — 科目模板
2. `t_tax_rule` — 税率规则
3. `t_account_mapping` — 发票/费用 → 科目映射
4. `t_ai_call_log` — AI 调用记录
5. `t_audit_log` — 操作审计
6. `t_sequence` — 凭证编号序列

DDL 集中放 `sql/V2__optimization.sql`，手动执行一次即可。

## 新增依赖（只有 2 个）

- `spring-boot-starter-aop`（做审计日志用）
- `spring-boot-starter-test`（做测试用）

## 已发现的现存 Bug

- **凭证编号全局唯一索引**：两个用户同一天录凭证必然撞号（不只是并发问题）
- **利润表只算单边**：有红字冲销时金额会错
- **AI 流式回复拿不到当前用户**：需要在请求开始时把用户 ID 存好传进去
